# Борлуулалт (borluulalt)

[![CI](https://github.com/XalMorak/borluulalt/actions/workflows/node.js.yml/badge.svg)](https://github.com/XalMorak/borluulalt/actions/workflows/node.js.yml)

Бар/рестораны борлуулалт, нөөц, илгээлт, тайлангийн веб апп.

**Live:** [borluulalt-xalmorak.vercel.app](https://borluulalt-xalmorak.vercel.app)

## Юу хийдэг вэ

- Ажилтан: өдөр, ээлж, байршил, тек сонгоод пиво эсвэл вино борлуулалт оруулна
- Ахлах: тойм, илгээлт, тайлан, нөөц, хэрэглэгч, түүх. Тойм/Илгээлт/Тайлан дээр **зөвхөн өнөөдрийн** илгээлт + ажилтан бүрийн өнөөдрийн илүү/дутуу
- Нягтлан: табууд **Илгээлт | Хэрэглэгч | Ростер | Тайлан**. Бүх илгээлт (Firebase `submissions` + `inbox`), шүүлт (ростер, огноо, ажилтан, байршил, тек, төрөл), ажилтан тус бүрийн илүү/дутуу, дэлгэрэнгүй (зөвхөн харах), Excel, 14 хоногийн ростер (засах/устгах), төлөлт. **Тайлан**: хураангуй, өдөр, байршил, ээлж, тек, бараа, тооцоо (дутуу үлдэгдэл), хэвлэх, Excel. **Хэрэглэгч нэмэх / засах / устгах** (өөрийгөө болон сүүлийн Ахлахыг устгах боломжгүй)
- Пиво ба вино тусдаа. Тойм / илгээлт / тайлан дээр Пиво | Вино | Нэгдсэн
- Нөөц байршлаар: Оюут бар, Манлай бар, VIP, POWER. Ахлахын **Нөөц** таб пиво + вино нэг хүснэгтэд (Бүгд | Пиво | Вино шүүлт, хайлт, нэг "Бүгдийг хадгалах"). Тусдаа "Вино" таб байхгүй болсон
- Түр хадгалалт (утас, Safari)
- Үүлэн синк: серверээс **зөвхөн нэвтрэх үед болон "Мэдээлэл шинэчлэх" дарахад**, зөвхөн өөрчлөгдсөн хэсгийг татна (delta). Арын timer/realtime татал байхгүй

## Stack

JavaScript · Firebase Realtime Database · Vercel

## Өгөгдөл

Firebase зангилаа `borluulalt`. Илгээлт: ажилтан + огноо + ээлж + **байршил**.

- `inbox/{id}` — ажилтны илгээлт (шууд)
- `submissions` — ахлахын нэгтгэсэн жагсаалт
- `rosters/{r_YYYYMMDD}` — нягтлангийн 14 хоногийн ростер
- `payments/{key}` — нягтлангийн төлөлтийн тэмдэглэл
- `deleted/{t_key}` — ахлахын устгасан илгээлтийн тэмдэг (дахин гарч ирэхгүй; тухайн ээлжийг дараа нь дахин илгээвэл харагдана)

- `_meta/{node}` — өөрчлөлтийн тэмдэг (бичих бүрт шинэ token). Delta синк үүнийг харьцуулж, өөрчлөгдсөн зангилааг л татна

### Delta синк (`net_gate.js`)

| Зангилаа | Хэрхэн шинэчилнэ |
|---|---|
| `inbox` | `orderByChild("submittedAt").startAt(сүүлийн синк − 15 мин)` |
| `deleted` | `orderByChild("at").startAt(сүүлийн синк − 15 мин)` |
| `users`, `products`, `wines`, `submissions`, `logs`, `rosters`, `payments` | `_meta/{node}` (эсвэл хуучин клиентийн root `updatedAt`) өөрчлөгдсөн үед л бүтнээр |

Төхөөрөмж дээр анх удаа (эсвэл 7 хоног тутам) зангилааг бүтнээр татна. Firebase rules-д индекс нэмэх шаардлагатай (индексгүй бол query ажиллана, гэхдээ сервер бүх зангилааг илгээнэ):

```json
"borluulalt": {
  "inbox":   { ".indexOn": ["submittedAt"] },
  "deleted": { ".indexOn": ["at"] }
}
```

Эрх: `employee` (Ажилтан), `supervisor` (Ахлах), `accountant` (Нягтлан). Ахлахын Хэрэглэгч таб эсвэл Нягтлангийн Хэрэглэгч таб дээр эрх сонгоно. Ахлах / Нягтлан эрхэд PIN заавал (Нягтлангийн хуудаснаас нэмэх/засах үед).

- `users/{id}` — хэрэглэгч (нэр, эрх, PIN)
- `products` — пиво/бар бараа (`stockByLoc`, `stock` = нийлбэр)
- `wines` — вино/бусад бараа, id ≥ 100 (`stockByLoc`, `stock`)

## Нэвтрэлт ба аюулгүй байдал

`api/` дахь Vercel function-ууд (`/api/login`, `/api/pin`, `/api/config`) PIN-ийг серверт hash-аар шалгаж Firebase custom token өгнө.
`sec_login.js` нь `LOGIN_MODE` (legacy → transition → secure) feature flag-ээр асаана; env тохируулаагүй бол хуучин нэвтрэлт хэвээр.
Rules (`security/`), PIN migration, нэвтрүүлэх дараалал: [security/README.md](security/README.md).
